# Geometric-Labs

[Open the Geometric Labs website](https://biochainai.github.io/Geometric-Labs/)
· [Research IDE](https://biochainai.github.io/Geometric-Labs/research-ide/index.html)

An exact-arithmetic Python reference engine and reproducible verification lab
for Hurwitz geometry, quaternion state chains, and 64-stream routing models.
The core and verification code require **Python 3.10+ and no third-party runtime
dependencies**. Physical calibration uses floating point in separate modules;
lattice, CRT, quaternion-chain, and balancer computations use exact integers.

## Quick start

From this checkout:

```sh
python3 verification/verify_geometric_labs_suite.py
make verify-all
make test-pillars
make vectors
make check-vectors
python3 verification/01_accessibility/test_float64_vs_gram_tqf.py
```

`make verify-all` runs all five master pillars, all 16 modular test files, and
checks committed golden vectors without overwriting them. The supplied documents
call these 14 suites, but enumerate 16. Tests discover correctly through the
numbered package directories. The master is standalone; package development
uses `PYTHONPATH=src`, or optionally `python3 -m pip install -e .`.

## Architecture and five verification pillars

| Pillar | Library | Checks |
|---|---|---|
| Accessibility | hurwitz, s5_hyperbolic_tree | exact Gram vs float64 cancellation, reduced words, spinor cycles |
| Calibration | calibration/ | Cramer cubit, caller-supplied GUM, Cs pulse windows, coherence and frame fitting |
| Certification & validation | certification/, garner_crt | wheel proposal filter, packed prime sieve, MR12, CRT bijection |
| Quaternion blockchains | blockchain/, tile_codec | noncommutative scan, open-boundary holonomy, Lucas checkpoints, halo and hash chain |
| Stream threading | threading/ | 64 routes, balancer closure, erasure recovery, exact phases and pruning |

Hurwitz coordinates are always doubled: `(2,0,0,0)` represents one; valid
coordinates are all even or all odd. S5 addresses explicitly use ordinary
integer coordinates. Core cubes are centered at the origin with bounds
`[-1,1]^3`, `[-2,2]^3`, and `[-4,4]^3`. Outer products act in reverse
chronological order; inverse middle-gear increments multiply chronologically
on the right. Tests use a nonidentity endpoint to catch accidental cancellation.

## Conformance and provenance

Five deterministic JSON files in `spec_sync/golden_vectors/` contain all 16 tile
envelopes, the full 24-unit multiplication table, S5 paths, CRT boundaries and
seeded samples, a 720-state delta chain, full SHA-256 root, and balancer routes.
`spec_sync/generate_golden_vectors.py --check` fails on byte drift. These vectors
are a **local reference profile**; Codex shape payload semantics were not supplied.
See the [tile profile](spec_sync/einstein_tile_64bit_rfc.md) before implementing bindings.

The [architecture blueprint](docs/architecture_blueprint.md) and original runner
under `verification/reference/` preserve the attached sources. The runnable
master corrects an inaccurate float64-zero assertion and an unhashable anchor
signature; details and remaining specification limits are in
[specification status](docs/specification_status.md). Tests are executable
conformance evidence, not proofs of the blueprint's physical or security claims.

The [research archive](Research_IDE/archive/README.md) preserves the first eleven PDFs
with hashes, revision families and reading lists across eight repositories. The earlier
[paper intake manifest](docs/papers/README.md) links to that central library. The supplied
[interactive walkthrough](interactive/geometric_engine_8_step_walkthrough.html)
is preserved unchanged; browser assets may require Internet access.

## Tooling

CI runs on Python 3.10, 3.11, and 3.12 and checks standalone test execution.
`make bench` reports the reference runner's elapsed time; it is not a controlled
hardware benchmark. `make clean` removes generated bytecode and build outputs,
leaving golden vectors and source intact. No services, credentials, GPU, or
external database are required for the Python development workflow.
